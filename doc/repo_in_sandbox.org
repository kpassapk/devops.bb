* Intro

In [[file:getting_started.org][getting_started.org]] we used a workbook as a way for the agent to
ask to run commands on your machine via org-babel source code
blocks. This is useful in an incident, or when performing a discovery
task that may involve external systems.

=devops.bb= uses a similar mechanism to transport project code from
the sandbox to your machine.

Let's see how, through an example.

The repository is [[https://github.com/kpassapk/bb-slug][bb-slug]], one Babashka function, =slugify=, that turns
a title into a slug. It drops accented letters: ="Año Nuevo"= becomes
="a-o-nuevo"=. The task is to fold them, so it becomes ="ano-nuevo"=.

The task a heading in a workbook /outside/ the repository.

#+begin_example
~/work/bb-slug/accents/work.org   * TODO Fold accents   :BRANCH: accents   :BASE: main
#+end_example

The heading's =:REPO:= names the checkout; devops-bb never looks for the
repo where the workbook is. (Here you write the file by hand. Making it
from a =work/= file in the repo, running several at once, and copying it
back when the task is done, is aly-root's job, not devops.bb's.)

The heading gets a container and an attach, and here a git worktree,
to run the branch on the host (optional: landing needs none). The agent
never sees your checkout, your worktree or your =.git= (hooks and config
in it run code). The repo travels as a /bundle/, a single file of git
objects and refs, through the workbook's directory:

1. You seed =bb-slug.bundle= into the workbook's directory.
2. The agent clones it into its own copy in the container, edits, tests
   and commits there, and bundles its new commits back.
3. You fetch that into =refs/sandbox/*=, read the commits, and only
   then move your branch. ("land" the commits.)
4. You push. It is the one step that needs a credential, so it is a
   block you run.

Midway, =main= moves under the task, as it does when someone else
merges, and the agent rebases onto it.

The workbook is not part of the PR: it is not in the repo at all. The
agent never commits under the repo's own =work/= either (its tools and
yours refuse).

Who owns what:

*Operator*:
- your checkout, the worktree if any, seeding, landing, the push

*Agent*:
- its clone in the container: edits, =bb test=, commits, the outgoing
  bundle

*Both*:
- the workbook, and the bundle files beside it

The steps use the =devops-bb= tasks =bundle seed=, =bundle land=,
=bundle status= (you) and =repo clone=, =repo handoff=, =repo rebase=
(the agent). =devops-bb= is =bin/devops-bb= of
this repo, on your =PATH=.

* Create the workbook                                              :workbook:

#+begin_src org :tangle work.org :mkdirp yes
  #+TITLE: bb-slug: accents
  #+PROPERTY: header-args:sh :results output

  * TODO Fold accents
  :PROPERTIES:
  :REPO:   ~/src/github.com/kpassapk/bb-slug
  :BRANCH: accents
  :BASE:   main
  :END:

  =slugify= drops accented letters: "Año Nuevo" becomes "a-o-nuevo".
  Fold each to its base letter (é to e, ñ to n), so it becomes
  "ano-nuevo". Add tests, run =bb test=, and commit.
#+end_src

The heading does not say what happens to a letter with no base letter
(ß, ø), on purpose: see what the agent decides, and whether its Result
says so.

** Claude                                                               :box:

With point in the block below, try =devops-run-in-terminal=

#+begin_src sh
  claude
#+end_src

Prompt:

#+begin_example
  Use the devops-bb-sandbox skill. Do the heading "Fold accents" in
  /work/work.org.
#+end_example

The "what" is the heading, and the "how" is the skill.

What to look for:
- Claude runs =devops-bb status=, then =repo clone --heading "Fold
  accents"=, and reads =slugify= in its own clone. It writes no block:
  all of it is uncredentialed.
- It runs =bb test= itself, with =git --no-pager=, and commits
  =src/slug/core.clj= and its test, and nothing under the repo's
  =work/=. Then it runs =repo handoff= and says which branch the bundle
  holds.
- It adds a =** Result= under the heading, after checking =modified=. It
  does not try to push.
- It does not use a REPL or =clj=: the image has Babashka only.

* Main moves                                                           :repo:

* Push (optional)                                                      :repo:

The push is the one step that needs a credential, so it is a block you
run. You need write access to the remote; otherwise skip this, or push
to your own fork.

#+begin_src sh :eval never-export
  git push origin accents
  gh pr create --head accents --base main --title "Fold accents" --body "Written in a sandbox."
#+end_src

* Try to break it

Run these from a second terminal.

- Put a repo in the workbook directory: =podman exec box-slug git clone
  ~/bb-slug /work/bb-slug=. The mode line says sandbox: SUSPENDED (a
  =.git= is a dot-path) and runs are refused. Remove it.
- Have Claude commit a file under the repo's =work/= in its clone. =repo
  handoff= refuses: "commits touch work/". If a bundle with one gets to
  the host anyway (=git bundle create= by hand), =bundle land= refuses
  it too.
- Plant a hook in the clone: =echo 'touch /tmp/pwned' >
  ~/bb-slug/.git/hooks/post-checkout=, then hand off and land. The hook
  is not in the bundle, and =/tmp/pwned= does not exist on your host.
- Ask Claude to push. It has no credentials, and the push fails in the
  container (=podman exec box-slug ls ~/.ssh ~/.config/gh= finds
  neither).
- Edit the same line of =slugify= on =main= by hand, re-seed with
  =--rebase= and have Claude run =repo rebase=. It exits 2 and names the
  file.
