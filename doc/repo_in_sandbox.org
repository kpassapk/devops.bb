* Intro

In [[file:getting_started.org][getting_started.org]] the agent only read your machine. Here it changes
code, in two pieces of work that depend on each other, and you decide
whether any commit ever leaves your machine.

The repository is [[https://github.com/kpassapk/bb-todo-api][bb-todo-api]], a small todo service in Babashka. It is
built in two parts, and the second needs the first:

- =todos.core=: the model, pure functions over a store.
- =todos.api=: a Ring handler over the model.

The workbook lives /in/ the repo, in =work/=, and each part is a heading
in it:

#+begin_example
* TODO Core: completing todos   :BRANCH: core   :BASE: main
* TODO API                      :BRANCH: api    :BASE: core
#+end_example

Each heading gets its own git worktree, its own container and its own
attach. The API is cut from core, so its PR is /stacked/ on core's. (A
heading with =:BASE: main= is an ordinary, independent PR; nothing here
needs a stack.) The agent never sees your checkout, your worktrees or
your =.git= (hooks and config in it run code). The repo travels as a
/bundle/, a single file of git objects and refs, through the workbook's
directory:

1. You seed =bb-todo-api.bundle= into the worktree's =work/=.
2. The agent clones it into its own copy in the container, edits, tests
   and commits there, and bundles its new commits back.
3. You fetch that into =refs/sandbox/*=, read the commits, and only
   then move your branch. ("land" the commits.)
4. You push. It is the one step that needs a credential, so it is a
   block you run.

The workbook is not part of the PRs. The agent never commits under
=work/= (its tools and yours refuse), and each worktree's =work/= is
only a working copy of the workbook.

Who owns what:

*Operator*:
- your checkout, the worktrees, seeding, landing, the push

*Agent*:
- its clone in the container: edits, =bb test=, commits, the outgoing
  bundle

*Both*:
- the workbook, and the bundle files beside it

The steps use the =devops-bb= tasks =worktree add=, =worktree seed=, =worktree land=,
=worktree status= (you) and =repo clone=, =repo handoff=, =repo rebase= (the
agent). =devops-bb= is =bin/devops-bb= of this repo, on your =PATH=.

  "The todo model. A store is a plain map; every function is pure and
  returns a new store, so there is no I/O here.")

(def empty-store {:next-id 1 :todos {}})

(defn add
  "Add a todo titled TITLE. Returns [store todo]."
  [store title]
  (let [id   (:next-id store)
        todo {:id id :title title :done? false}]
    [(-> store
         (assoc-in [:todos id] todo)
         (update :next-id inc))
     todo]))

  "Every todo, oldest first."
  [store]

  base's change, not this branch's.

not exist, on purpose: the second finds out.

+(ns todos.api
+  "A Ring handler over todos.core. The store lives in an atom; requests
+  and responses are JSON."
+  (:require
+   [cheshire.core :as json]
+   [todos.core :as core]))
+
+(defn- respond
+  [status body]
+  {:status  status
+   :headers {"Content-Type" "application/json"}
+   :body    (json/generate-string body)})
+
+(defn- read-json
+  "The request body parsed as JSON with keyword keys, or nil when it is
+  missing or not JSON."
+  [request]
+  (when-let [body (:body request)]
+    (try (json/parse-string (slurp body) true)
+         (catch Exception _ nil))))
+
+(defn- update-store!
+  "Apply F, a store -> [store x] function, to the atom and return x."
+  [store-atom f]
+  (let [result (volatile! nil)]
+    (swap! store-atom (fn [store]
+                        (let [[store x] (f store)]
+                          (vreset! result x)
+                          store)))
+    @result))
+
+(defn- list-todos [store-atom]
+  (respond 200 (core/all @store-atom)))
+
+(defn- create-todo [store-atom request]
+  (let [title (:title (read-json request))]
+    (if (and (string? title) (seq title))
+      (respond 201 (update-store! store-atom #(core/add % title)))
+      (respond 400 {:error "title must be a non-empty string"}))))
+
+(defn- complete-todo [store-atom id]
+  (if-let [todo (update-store! store-atom #(core/complete % id))]
+    (respond 200 todo)
+    (respond 404 {:error (str "no todo with id " id)})))
+
+(defn handler
+  "A Ring handler over the store in STORE-ATOM:
+
+    GET  /todos                 every todo
+    POST /todos                 {\"title\": ...} adds one, 201
+    POST /todos/:id/complete    marks it done, 404 if there is none"
+  [store-atom]
+  (fn [{:keys [request-method uri] :as request}]
+    (let [complete-id (some-> (re-matches #"/todos/(\d+)/complete" uri)
+                              second
+                              parse-long)]
+      (cond
+        (and (= uri "/todos") (= request-method :get))  (list-todos store-atom)
+        (and (= uri "/todos") (= request-method :post)) (create-todo store-atom request)
+        (and complete-id (= request-method :post))      (complete-todo store-atom complete-id)
+        :else (respond 404 {:error "not found"})))))

run, in the order the stack lands: core to =main=, the API to core. You
need write access to the remote; otherwise skip this, or push to your
own fork.
